# detections/

Detection-as-code: one Sigma rule per technique in
[`attack/techniques.py`](../attack/techniques.py), each proven to fire
against synthetic fixture telemetry — no live SIEM required. This is what
makes `make detections-test` runnable in CI, the same "testable without a
live lab" design as `attack/runner.py`'s dry-run mode.

## Layout

| Path | Purpose |
|---|---|
| `sigma/{technique_id}.yml` | One Sigma rule per technique — filename must match the technique's `id` in `attack/techniques.py`, that's how `test_runner.py` finds it |
| `fixtures/{technique_id}.json` | `{"matching": [...], "non_matching": [...]}` — synthetic event dicts using raw Sigma field names (`EventID`, `TicketEncryptionType`, etc.), not full ECS/Winlogbeat-shaped documents |
| `matcher.py` | Evaluates a parsed Sigma rule's condition tree (AND/OR/NOT, modifiers) against one event dict — reuses pySigma's real parser, doesn't reimplement Sigma's condition language |
| `coverage.py` | Pure function building the attack→detection coverage matrix from a list of `TechniqueCoverage` results |
| `test_runner.py` | Orchestrates the above: parse + semantically validate every rule, run its fixtures, write `coverage_matrix.json` |
| `coverage_matrix.json` | Generated by every `make detections-test` run and committed — feeds the Phase 5 platform's ATT&CK Navigator-style heatmap (not built yet) |

## Adding a new rule

1. Write `sigma/{technique_id}.yml` — must include `references:` citing the
   technique's `attack_url` and a `tags:` entry `attack.{attack_id lowercased}`
   (both checked by `test_runner.py`'s `_validate_rule_semantics`).
2. Write `fixtures/{technique_id}.json` with at least one `matching` and
   one `non_matching` event — a rule with no `non_matching` fixture can't
   prove its filters actually filter anything (`tests/test_detections_runner.py`
   enforces this).
3. Run `make detections-test` (or `pytest tests/test_detections_runner.py`).

## Why not `sigma-cli`'s `sigma check`?

It's still useful for deeper validation (`sigma check detections/sigma/`,
installed via the `sigma-cli` dev dependency) but `test_runner.py`
deliberately doesn't call it automatically: its tag validator fetches
MITRE ATT&CK tactic data from GitHub over the network, which would make
`make detections-test` fail offline or on an egress-restricted CI runner.
`test_runner.py` uses pySigma's local parser directly instead — real
schema/syntax validation, zero network dependency.

## Status

All 6 rules pass `make detections-test` (100% coverage) against
hand-authored fixtures — see BUILD_LOG.md for when. **Not** validated
against real telemetry from a running lab, since none exists yet (see
ROADMAP.md). The fixtures are a reasonable-effort approximation of real
Sysmon/Security event shapes, not captured from an actual Windows host.
